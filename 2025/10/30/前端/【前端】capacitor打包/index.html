capacitor将web项目打包为iOS/Android原生应用

Posted on 2025-10-30 Edited on 2025-11-12 In 前端

Capacitor 介绍

Capacitor 提供了一套统一的、以 Web 为中心的 API，使应用程序能够尽可能地遵循 Web 标准，同时还能在支持的平台上访问丰富的原生设备功能。

即，它可以把 web 端的项目打包为 app，从而在安卓/ios 上面作为一个 app 运行。

但 Capacitor 本质上只是Web 技术（Vue/React 等）+ 原生容器（WebView）= App，即它是通过在 app 中引入 webview 来进行支持的，与原生编写 app 还是有区别的，它用 WebView 包一层网页 → 在 App 里运行你的 Web App（HTML/CSS/JS），通过桥（bridge）调用原生功能。

与其他框架比较：

方案 原理 优点 缺点
手动 WebView 自己嵌网页 简单、可控 无桥接、维护重
Capacitor Web + 桥接层 快速、生态强、可扩展原生功能 性能略逊
NativeScript-Vue / React Native / Flutter JS/TS → 原生控件 原生性能、体验优 需重写前端逻辑
Tauri/Electron 桌面 Web 壳 跨平台桌面应用 体积大、移动端不可用

使用

环境

  • Host 项目：Vue3@3.5.18+TS+Vite@7.1.2
  • Remote 项目：React@18.2.0+TS+Vite@6.3.6(LiberChat 项目)
  • Nodejs 版本：v23.11.1
  • java: 21.0.9 2025-10-21
  • NPM 版本：10.9.2
  • 安装依赖工具：npm
  • @capacitor/ios / @capacitor/android 版本：7.4.4
  • @capacitor/cli 版本: 7.4.4
  • @capacitor/core 版本: 7.4.4
  • android studio 版本：21.0.7+-13880790-b1038.58 amd64

当前使用的是 windows，所以安装 android studio 来进行预览，如果是 mac，那么使用 Xcode

初始化

  • 安装依赖

  • 初始化

    执行 cap init 时会让你输入：

    • app 名称（比如 MyApp）

    • 包名（比如 com.example.myapp）

    这会生成一个 capacitor.config.ts 或 capacitor.config.json。

  • 生成原生项目结构

此时项目根目录会出现 android/ios 文件夹

打包运行

  1. 将原项目执行打包命令，记得在项目根目录生成dist文件夹，因为 capacitor 打包 app 时是通过dist文件夹的

  2. 运行 npx cap sync 命令：将 web 代码同步到原生项目

  3. 运行npx cap run android, 会直接打包两个 cmd 以及打开一个模拟器系统镜像（Android Studio）

调试

打开的模拟器中没有调试工具，这个时候访问 chrome://inspect/#devices 会在 Remote Target 下看到有个 localhost 相关的，点击inspect

然后就会出现一个 devtools 的调试框，就可以进行调试了

状态栏

在capacitor.config.ts中添加android属性

  • 控制页面内容显示在状态栏下方，即状态栏不遮挡内容

    • contentInset 参数控制内容如何适应iPhone/iPad的安全区域（如刘海屏、底部横条等区域）

    • 当设置为 "always" 时：

    • 内容会始终考虑设备的安全区域边缘

    • 确保重要UI元素不会被刘海、底部指示器等遮挡

    • 适用于全屏沉浸式应用，让内容在安全区域内正确显示

    • 配合 viewport-fit=cover 使用效果最佳

    • adjustMarginsForEdgeToEdge 参数控制是否自动调整WebView的边距以适应系统UI

    • 当设置为 "auto" 时：

    • 系统会根据Android版本和设备特性自动决定是否启用边缘到边缘显示

    • 在支持的设备上，应用可以延伸到屏幕边缘，包括系统导航栏和状态栏区域

    • 系统会自动添加适当的内边距，防止内容被系统UI遮挡

    • 实现类似iOS的沉浸式体验，但根据Android系统规则自动适配

组合使用的效果

这两个配置一起使用时，可以实现：

  1. 跨平台的沉浸式UI体验
  2. 内容自动适应不同设备的异形屏和安全区域
  3. 无需手动编写大量平台特定的适配代码
  4. 提供更现代、全屏的用户界面

这些配置通常与CSS中的 safe-area-inset-* 变量和 env(safe-area-inset-*) 函数配合使用，以实现更精细的布局控制。
