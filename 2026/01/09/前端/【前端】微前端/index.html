微前端

微前端（Micro-Frontends）是一种将大型前端应用拆分为多个可独立开发、独立部署、独立运行的前端子应用的架构思想

出现原因

在传统 SPA / MPA中，随着业务增长，会出现：

  • 项目体积巨大、构建慢

  • 多团队协作互相影响（改一处，牵一片）

  • 技术栈难以升级（历史包袱）

  • 发布风险大（一次发布影响全站）

微前端核心特性

特征 说明
独立开发 每个子应用一个仓库
独立部署 子应用可单独上线
技术栈无关 React / Vue / Angular 可共存
运行时集成 在浏览器中组合
团队自治 团队边界清晰

微前端实现分类

  • 特性
    1. 独立开发部署：每个子应用可以独立运行和部署
    2. 技术栈无关：React 和 Vue 应用可以共存
    3. 应用隔离：JS 沙箱和样式隔离防止冲突
    4. 应用通信：通过 props 和全局状态实现数据传递
    5. 按需加载：只加载当前激活的应用

iframe 方案

最简单但隔离性最强的方案：

  • 优点:
    完全隔离（样式、JS、全局变量）
  • 缺点:
    通信复杂、性能差、URL 不同步、UI 不连续

js 沙盒

目标: 运行时隔离 - 在同一个浏览器环境中创建多个隔离的 JavaScript 执行环境 - 防止不同应用的全局变量、副作用互相污染 - 类似操作系统的进程隔离概念

  • 应用加载：

  • 应用注册与启动

    • registerMicroApps: 注册子应用配置（name、entry、container、activeRule）
    • start: 启动 qiankun，劫持路由事件，开始监听路由变化

  • 资源加载流程

    路由匹配 → fetch HTML → 解析 JS/CSS → 创建沙箱 → 执行 JS → 调用生命周期

  • 沙箱隔离（核心）

    使用 Proxy 拦截 window 访问：

    • 读取：优先从 fakeWindow 读，否则从真实 window 读
    • 写入：只写入 fakeWindow，不污染真实 window
    • 使用 with 语句改变代码执行作用域

  • 样式隔离

    • 实验性隔离：动态添加 data-qiankun 属性作为 CSS scope
    • 严格隔离：使用 Shadow DOM 完全隔离样式

  • 生命周期管理

    子应用必须导出三个函数：

    • bootstrap: 应用初始化（只调用一次）
    • mount: 应用挂载（每次进入时调用）
    • unmount: 应用卸载（每次离开时调用）

  • 路由劫持

    劫持以下 API 监听路由变化：

    • history.pushState
    • history.replaceState
    • popstate 事件
    • hashchange 事件

  • 全局状态管理

    使用观察者模式实现跨应用通信：

    • initGlobalState: 初始化全局状态
    • onGlobalStateChange: 监听状态变化
    • setGlobalState: 修改状态（通知所有订阅者）

模块联邦

子应用配置

核心原理：

  • 子应用需要导出 bootstrap、mount、unmount 三个生命周期函数
  • qiankun 会在适当的时机调用这些函数

父容器使用

  • 注册
    原理：

    • qiankun 会将这些配置存储在内部的 apps 数组中
    • 每个应用配置包含：name、entry、container、activeRule
    • activeRule 用于路由匹配，决定何时加载/卸载应用

  • 初始化监听全局状态

    原理：

    • 创建一个全局的状态管理器
    • 使用观察者模式，所有子应用可以订阅状态变化
    • 任何应用修改状态，其他应用都会收到通知

  • 启动 qiankun
    原理详解：

    1. 劫持路由：监听 popstate 和 hashchange 事件
    2. 匹配应用：根据当前路由匹配 activeRule
    3. 加载应用：fetch HTML -> 解析资源 -> 创建沙箱 -> 执行 JS
    4. 挂载应用：调用子应用的 mount 生命周期

  • 修改全局状态

路由

qiankun 同时支持 history 路由和 hash 路由，可以单独使用，也可以混合使用

  • History 路由

    URL 示例：

    • 主应用：http://localhost:8080/
    • React 子应用：http://localhost:8080/react
    • Vue 子应用：http://localhost:8080/vue

  • Hash 路由

    URL 示例：

    • 主应用：http://localhost:8080/#/
    • React 子应用：http://localhost:8080/#/react
    • Vue 子应用：http://localhost:8080/#/vue

  • 混合路由

    • 场景 1：主应用 History + 子应用 Hash
    • 场景 2：主应用 Hash + 子应用 History

  • 路由匹配规则详解

    1. 字符串匹配
    1. 数组匹配（多个路径）

    activeRule: ['/react', '/app1'] // 匹配多个路径

    1. 函数匹配（自定义规则）
    1. 正则匹配

    activeRule: /^\/react/ // 使用正则表达式

qiankun 和模块联邦区别

对比维度 JS 沙箱 模块联邦
本质 运行时隔离方案 构建时共享方案
目标 防止冲突和污染 代码复用和优化
隔离性 强隔离 弱隔离
性能 较低（重复加载） 较高（共享加载）
灵活性 高（动态加载） 中（需要配置）
版本管理 独立版本 需要协调
适用场景 多技术栈、第三方应用 同技术栈、组件共享
学习成本 中等 较低
